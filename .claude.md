# Project context for Claude

## What this is
Next.js 16 App Router · TypeScript (strict) · TanStack Query · Axios · Zustand

## Critical: no Next.js API routes

This app has **zero** Route Handlers under `src/app/api/`. All data comes from an **external backend**.

- Browser client: `@/lib/api` → `NEXT_PUBLIC_API_DEV` / `NEXT_PUBLIC_API_PROD`
- Server client: `@/lib/server-api` → same external base URL
- Paths like `/api/v1/...` in services are **external API paths**, not this Next.js app

**Never** create BFF proxies, webhooks, or Route Handlers in this repo unless explicitly requested.

Auth uses the same `lib/api` client as other features (no separate auth routes). Session orchestration lives in `repositories/auth/` per AGENTS.md.

## SSR-first data fetching

| Context | How to fetch |
|---|---|
| `app/**/page.tsx` (Server Component) | `await` functions from `@/services/server/*.server.ts` |
| Client Component (interactive) | Hooks in `@/hooks/*` → client services in `@/services/*.service.ts` |

Pages must **not** use client services or `@/lib/api` for initial render.

## Layered architecture

```
External backend (NEXT_PUBLIC_API_*)
     ↓
services/server/*.server.ts   ← SSR pages (server-only)
services/*.service.ts         ← hooks / mutations (client-only)
     ↓
hooks/                        ← TanStack Query (client only)
     ↓
components/ + app/            ← UI
```

### Folder map

| Layer | Location | Responsibility |
|---|---|---|
| Server services | `services/server/*.server.ts` | SSR — `createServerApi()` |
| Client services | `services/*.service.ts` | Mutations & client refetch — `lib/api` |
| Hooks | `hooks/*.ts` | Client caching & state |
| Types | `types/*.ts` | API shapes, Zod DTOs, transforms |
| Errors | `lib/errors.ts` | AppError, normaliseError |
| Env | `lib/env.ts` | Zod-validated env + `getApiBaseUrl()` |

### Dependency rules
- `app/` → `services/server/` only (never client services, never hooks)
- `hooks/` → client `services/` only
- `components/` (client) → `hooks/` only — never services or api directly
- `services/server/` → `lib/server-api`, `types/`, `lib/errors` — must have `import 'server-only'`

## SEO
- `buildMetadata()` on every public page
- `noIndex: true` on auth, cart, dashboard, account pages
- `app/sitemap.ts` · `app/robots.ts` · `app/manifest.ts`

## Code style
- Google ESLint · max 100 chars · `import type` for type-only imports
- **Commits**: `[type] PW-123 description` — e.g. `[feat] PW-11 add product gallery` (see `commits.mdc`)
- **Pre-commit**: lint-staged → type-check → build must all pass before commit
- Never access `process.env.*` — use `@/lib/env`

## Testing

See `@AGENTS.md` § Tests for full policy.

- Tests live in `tests/` mirroring `src/` — not colocated under `src/`
- **Components:** React Testing Library; mock hooks/context
- **Logic:** mock at `api` / service boundary
- **Per export or UI state:** 2 happy + 2 failure scenarios
- **Coverage:** `pnpm test:coverage` before PR — 90–95% target on touched modules (WARN only, not commit-blocking)
